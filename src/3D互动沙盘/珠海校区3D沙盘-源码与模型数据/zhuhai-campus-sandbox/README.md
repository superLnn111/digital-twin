# 中山大学珠海校区 · 3D互动沙盘 r4

独立 HTML 微缩校园模型。双击 `outputs/中山大学珠海校区-3D互动沙盘.html`，在 Chrome、Edge 等支持 WebGL 的现代浏览器中打开即可；无需安装、启动服务器或联网加载资源。

版本 **4.0（r4）**，更新于 **2026年11月3日**。

## 操作

| 功能 | 操作 |
| --- | --- |
| 环绕观察 | 鼠标左键拖动；触屏单指拖动 |
| 缩放 | 鼠标滚轮、右侧加减按钮；触屏双指捏合 |
| 平移 | 鼠标右键拖动，或 Shift + 左键；触屏双指移动 |
| 查看地标 | 点击建筑、标签或左侧搜索结果；手机点击底部“地标”打开列表 |
| 近看 | 在地标详情中点击“近看这个地点” |
| 快速视角 | 右侧鸟瞰、正北俯视、海岸、校园中轴 |
| 漫游 | 底部“校园漫游”自动访问七处地点；操作场景或点关闭可停止 |
| 环绕、日夜 | 底部按钮切换自动环绕和日夜照明 |
| 图层 | 显示/隐藏建筑、山林、标签及参考图中的规划/在建部分 |
| 对照原图 | 右上角“参考影像”，点击图片继续放大 |

七站顺序为：山顶天文台 → 天琴楼 → 教学楼东侧停车场 → 教学楼长轴 → 图书馆后山 → 图书馆 → 海琴4号。点击小地图可以改变观察中心；搜索到隐藏的规划建筑时，模型自动打开相应图层。科研试验场中的四台风机持续转动，不依赖相机自动环绕或漫游开关。

## 模型依据与精度

- **2026年11月2日至3日用户确认的校园现状及提供的天文台实拍，优先于旧总平面图和鸟瞰效果图。** 原始图面为《Zhuhai Campus Map.jpg》（2024年3月）及《Zhuhai Campus Map 3D view.png》（效果图，日期未知），不是当前实景扫描。
- 原始 `data/building-footprints.json` 保留 **102个轮廓**。构建时由 `apply-revisions.cjs` 应用用户修订，得到 **94个有效原始轮廓、36个庭院孔洞、7处水体、47个可搜索地标**，并加入天文台、停车场、试验场、四台风机和台阶等定制模型。94是轮廓记录数，不是建筑总栋数。
- 图书馆位于旧图“行政楼”位置，采用白色双翼体量；中缝台阶入口收窄并转弯，接后山长阶。原规划圆形图书馆、博物馆位置均改为植被小山丘，不再显示旧圆形建筑。
- 教学长轴为白色，**仅在隐湖南端现有道路经过处**设置两层高架空通道，穿楼中心约为1960×1248图面 `y=739`，开口范围 `y=730–748`。此前约 `y=657` 的人工斜向道路已移除。通道净高参数 **6.4是模型单位，不是实测米数**。
- 停车场位于教学长轴**东侧**：移除原六条红墙体量 `B078–B083` 后设置地面车位及出入口。**西侧 `B074/B074-2` 已恢复，瀚林1号保留原图的在建标识**，不再将西侧建筑位置当作停车场。
- 科研试验场位于音乐厅西侧、主路对面，位置经用户确认；围栏、试验板和设备细节为示意。场内新增**四台持续转动的三叶片水平轴风机**，白灰塔筒与机舱、混凝土基础和叶轮位置均为微缩表现，不是实测风机参数。
- 槿园中间楼 `B060` 按用户确认设为**3层**，不沿用周边宿舍的高层示意。运动场与跑道范围不种树；跑道采用胶囊形平面，道路采用平滑深灰铺装。
- 山顶天文台依据用户实拍表现白色主楼、偏置圆顶与围合体，位于**天琴楼西南后山的南峰**：主楼图面锚点约 `(457,700)`，平台中心约 `(470,700)`。r4将南峰改为与周边连续连接、自然起伏的宽缓山脊，**仅比其他最高山峰略高约10–15%**；观测台场地采用圆角平整区与柔和过渡。此排序、形态与高度均为用户指定的示意表达，**不是测量所得的真实最高峰或高程**。位置与参数以 `data/campus-revisions.json` 为准。
- 道路以 `data/road-design.json` 的独立中心线设计为准，由 `campus-road-design.js` 生成平滑铺装；保留隐湖南端的唯一穿楼道路。通往博雅苑的山谷连接路改为沿**榕园西侧**行进，原东侧连接路及其地形切槽已移除；走向为结合参考图关系的示意设计。
- 建筑高度、楼层、立面细部、地形高差、树木及海面均为可视化示意。没有测绘坐标、实测楼高或 DEM；模型单位不等同实测米。不能据此量测工程尺寸。
- 未被用户修订的规划/在建内容保留参考图状态，不把2024年规划图自动当作2026年建成现状。其中隐湖、若海的水面保留，规划状态指景观提升内容。
- 图面提供原始轮廓和相对关系，鸟瞰图用于形态参考；与本轮用户确认冲突时，按用户确认处理。

## 修改与重新生成

本项目是原生 HTML/CSS/JavaScript，使用本地固定版本 Three.js 0.160.1，无 npm 依赖。安装 Node.js 后，在项目目录执行：

```sh
node build.cjs
```

命令读取原始数据、应用用户修订，同时生成 `dist/index.html` 和上述中文名称的独立HTML，并内嵌库、数据与参考图片。修改现状修订应编辑 `data/campus-revisions.json`，修改道路中心线应编辑 `data/road-design.json`；不要把派生94条结果覆盖回原始102条轮廓。

若修改 `data/road-design.json` 中的 `routes[].points`，应先运行 `python data/generate_road_design.py` 重新生成道路几何与验证数据，再执行 `node build.cjs`。道路生成器需可用的Shapely；直接构建已有道路数据不需要Python。

| 文件 | 用途 |
| --- | --- |
| `shell.html`、`style.css` | 界面结构、视觉样式与响应布局 |
| `utils.js` | 坐标、地形、分类和工具函数 |
| `world.js`、`world-extra.js` | 建筑、庭院、植被、水体和三维场景 |
| `campus-roads.js` | 原图道路辅助与路面处理；r4道路设计以独立中心线配置为准 |
| `campus-road-design.js`、`data/road-design.json` | r4平滑道路中心线、穿楼道路及榕园西侧山谷连接路 |
| `data/generate_road_design.py` | 修改中心线后重建道路几何，并核对水体、建筑及场地避让 |
| `campus-specials.js` | 照片参考天文台、圆顶、平台与围栏 |
| `campus-sites.js` | 东侧停车场、科研试验场和图书馆后山台阶 |
| `campus-turbines.js` | 四台水平轴风机及独立于相机运动的连续叶轮更新 |
| `campus-landscape.js` | 两座小山丘的点选表面；山体高程与避树逻辑位于 `utils.js` |
| `app.js` | 相机、触屏、搜索、点选、七站漫游和图层 |
| `apply-revisions.cjs` | 构建时将原图数据转换为用户确认的r4模型 |
| `data/campus-revisions.json` | 建筑覆盖项、移除轮廓、山丘/场地参数和最终 `boardRing` |
| `reference/landmarks.json` | 原图44个地标；应用修订后为47个，名称与用途按用户确认更新 |
| `data/building-footprints.json` | 保留102条原始建筑轮廓、庭院孔洞和水体轮廓 |
| `data/terrain-triangulation.json` | 按最终边界精确裁切的5px共享顶点地形网格 |
| `data/generate_terrain_triangulation.py` | 从修订配置的 `boardRing` 重建地形网格与验证报告 |
| `assets/forest-mask.json` | 从参考图提取并平滑的林地范围，不是高程数据 |
| `assets/road-distance.json` | 道路距离采样，供道路周围地形平整与过渡使用 |
| `data/road-surfaces.json`、`data/roads-mask.png` | 道路铺装多边形与遮罩 |
| `assets/plan-reference.jpg`、`assets/aerial-reference.jpg` | 内嵌的总平面图与鸟瞰参考图 |
| `assets/observatory-reference.jpg` | 用户提供的天文台实拍 |
| `qa-r4.cjs`、`qa/r4-report.json` | 当前r4西侧连接路、柔和山脊及其余现状修订检查脚本和结果 |
| `qa-terrain-profile.cjs` | 南峰与其他峰高比较及横纵剖面采样，输出模型单位检查结果 |
| `qa/final-smoke.json` | 最终r4离线启动和手机检查；打包前由最终构建重跑 |
| `qa/r3-report.json` | r3历史检查记录；压缩包中放入 `qa/baseline-r3/` |
| `qa/revisions-report.json` | r2历史修订记录；压缩包中放入 `qa/baseline-r2/` |
| `data/*-validation.json` | 原始轮廓与当前地形网格的有效性记录 |

轮廓和地标坐标使用1960×1248图面，原点在左上，X向右、Y向下；三维场景映射为 `X = 图面X − 1000`、`Z = 图面Y − 640`，竖直方向为Y。高度由示意函数生成。底板边界以修订配置的 `boardRing` 为准，包含海岸和试验场；地形与裙边共享边界顶点，避免边缘锯齿与裂缝。

网页构建不需要Python。若重新提取轮廓或生成地形，相关脚本需对应的PIL、NumPy、OpenCV、Shapely依赖及可用输入路径；源码包不包含制作机的 `data/deps`。地形生成器需要PIL和Shapely，道路生成器需要Shapely。`qa-r4.cjs` 与 `qa-final-smoke.cjs` 使用Playwright/Chrome，其他电脑运行前应调整脚本中的本机依赖路径。`qa-terrain-profile.cjs` 使用Node.js。`qa-r3.cjs`、`qa-revisions.cjs` 为历史检查脚本，不用于证明r4结果。

## 验证

桌面与手机检查覆盖离线启动、旋转/平移/缩放、触屏、搜索点选、图层、日夜、漫游、参考图放大与布局。r4修订检查应核对榕园西侧博雅苑连接路、东侧旧路移除、南峰仅略高的连续起伏山脊及观测台场地过渡；同时保留东侧停车场、西侧建筑恢复、隐湖南端唯一架空通道、四台风机持续旋转、`B060`为3层、跑道避树及几何有效性检查。结果以对应版本的检查JSON为准。

当前修订报告为 `qa/r4-report.json`，最终离线启动和手机检查为 `qa/final-smoke.json`；两者应在r4最终构建后重跑，再生成压缩包。地形比例可另外运行 `node qa-terrain-profile.cjs` 检查。`qa/r3-report.json`、`qa/revisions-report.json` 分别作为r3、r2基线，源码包将其置于 `qa/baseline-r3/`、`qa/baseline-r2/`。早期 `qa/report.json`、`qa/landmark-audit.*` 保留在 `qa/baseline-v1/`，其中102轮廓/44地标和旧圆形建筑的检查不能代表r4。历史报告与当前报告分开保留。

最终构建与QA完成后，执行 `python make_package.py` 生成源码与模型数据压缩包；脚本先检查所列构建输入是否齐全。独立HTML另行交付，不依赖压缩包。
